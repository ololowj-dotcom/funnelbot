# Справочник настроек

Вся ваша воронка описана в одном YAML-файле `funnel.yaml`. Большую часть можно собрать, не трогая файл, через [конструктор воронки в админ-панели](funnel-builder.md); эта страница нужна для ручной правки и для возможностей, которых в конструкторе нет. Когда конструктор изменяет файл, он переписывает его в стандартном виде, поэтому написанные руками комментарии не сохраняются. Здесь перечислены все настройки. После любого изменения запускайте `funnelbot validate`: он показывает **все** ошибки сразу и подсказывает вроде «возможно, вы имели в виду 'buttons'?».

> English version: [../configuration.md](../configuration.md)

## Устройство файла

```yaml
bot:        # кто управляет ботом, язык, значения по умолчанию
consent:    # необязательно: экран «Согласен» перед началом воронки
payments:   # какие способы оплаты включены и их ключи
products:   # что вы продаёте и что получает клиент
start: welcome   # первый шаг
steps:      # диалог
```

## Секреты и файл .env

Никогда не пишите токены прямо в `funnel.yaml`. Положите их в файл `.env` рядом и ссылайтесь на них:

```yaml
payments:
  yookassa:
    shop_id: ${YOOKASSA_SHOP_ID}
    secret_key: ${YOOKASSA_SECRET_KEY}
```

- `${NAME}` заменяется значением `NAME` из `.env` или из окружения. Отсутствующее значение считается ошибкой.
- `${NAME:-default}` берёт `default`, если `NAME` пусто.
- Подстановки работают в любом текстовом значении файла.

## Длительности

`30s`, `10m`, `2h`, `1d`. Просто число означает минуты.

## Подстановки в текстах

В текстах шагов, напоминаний и выдаваемых сообщений можно использовать:

| Подстановка | Значение |
|---|---|
| `{first_name}` | Имя клиента |
| `{username}` | Его @username без @ |
| `{id}` | Его Telegram id |
| `{email}`, `{phone}`, любой `ask.key` | Ответ, который клиент дал раньше |
| `{product}` | Название продукта, только в `access.message.text` |

Значения экранируются автоматически, поэтому клиент не может внедрить разметку. Текст по умолчанию в HTML: `<b>жирный</b>`, `<i>курсив</i>`, `<a href="...">ссылка</a>`, `<code>код</code>`. Для обычного текста задайте `bot.parse_mode: none`.

Чтобы показать буквальные `{` или `}`, пишите `{{` или `}}`.

## bot

```yaml
bot:
  language: ru            # ru (по умолчанию) или en: язык всех встроенных сообщений
  admins: ["${ADMIN_ID}"] # id пользователей Telegram, которым доступна /admin. Необязательно: бота можно занять по ссылке
  manager_chat: ${MANAGER_CHAT:-}  # id чата, куда приходят карточки заказов и скриншоты оплат
  parse_mode: html        # html (по умолчанию) или none
  enforce_expiry: true    # false: никого не удалять из каналов, только вести дату окончания
  test_mode: false        # true: админам показывается бесплатная кнопка «Тестовая оплата»
  pay_style: success      # цвет кнопок оплаты: primary (синий), success (зелёный), danger (красный) или none
  texts:                  # переопределить любую встроенную фразу, см. ниже
    paid_thanks: "Спасибо, оплата прошла!"
```

- **admins**: свой id узнаете, отправив боту `/id`. Либо оставьте список пустым и воспользуйтесь ссылкой, которую печатают `funnelbot setup` и `funnelbot link`.
- **manager_chat**: создайте группу, добавьте туда бота и себя, отправьте в ней `/id` и скопируйте число (обычно начинается с `-100` или `-`). Обязателен, если используете кнопки `manager`, доступ `manager` или способ оплаты `manual`.
- **texts**: ключи встроенных фраз (полный список в `src/funnelbot/texts.py`): `back`, `home`, `agree`, `use_buttons`, `pay_now`, `pay_stars`, `pay_telegram`, `pay_yookassa`, `pay_crypto`, `pay_manual`, `pay_check`, `pay_waiting`, `pay_failed`, `pay_expired`, `paid_thanks`, `access_channel`, `access_until`, `access_renewed`, `access_reminder`, `access_expired`, `renew`, `join_approved`, `join_declined`, `manager_called`, `help`, `terms`, `paysupport`, `deleted`, `stopped`, `resumed` и другие. Неизвестный ключ считается ошибкой с подсказкой.

## consent

Показывает экран согласия перед всем остальным. Чтобы продолжить, клиент должен нажать кнопку. Рекомендуется, если вы собираете персональные данные (например, по 152-ФЗ или GDPR).

```yaml
consent:
  text: "Подтвердите, что согласны с условиями."
  agree: "Согласен"          # необязательно, по умолчанию встроенная фраза
  documents:
    - {title: Оферта, url: "https://example.com/terms"}
    - {title: Политика конфиденциальности, url: "https://example.com/privacy"}
```

Эти же документы показывает `/terms`.

## payments

Включайте нужные способы. Подробности и получение ключей: [Оплаты](payments.md).

```yaml
payments:
  stars: true
  telegram:
    provider_token: ${PROVIDER_TOKEN}
    currency: RUB
    need_email: false
    receipt: {vat_code: 1, tax_system_code: 1, payment_subject: service, payment_mode: full_payment, contact_key: email}
  yookassa:
    shop_id: ${YOOKASSA_SHOP_ID}
    secret_key: ${YOOKASSA_SECRET_KEY}
    return_url: https://t.me/your_bot
    currency: RUB
    receipt: {vat_code: 1, contact_key: email}
  crypto:
    token: ${CRYPTO_PAY_TOKEN}
    asset: USDT
    expires_in: 1h
  manual:
    text: "Переведите сумму на карту 0000 0000 0000 0000 и пришлите скриншот."
    currency: RUB
  poll_seconds: 20     # как часто проверяются заказы ЮKassa и Crypto Pay
  pending_ttl: 1d      # через это время неоплаченный заказ истекает
```

У каждого способа одна валюта: Stars всегда `XTR`, остальные используют заданные вами `currency`/`asset`. Продукт можно купить способом, только если у продукта есть цена в валюте этого способа.

`receipt` нужен для фискальных чеков (например, по 54-ФЗ). `contact_key` указывает ответ, в котором лежит email или телефон клиента, собранный шагом `ask`.

## products

```yaml
products:
  club:                              # id: строчные буквы, цифры, подчёркивание
    title: Закрытый клуб
    description: Закрытый канал с еженедельными материалами.
    image: files/club.jpg            # необязательная картинка на карточке продукта
    prices: {XTR: 500, RUB: 4900, USDT: 55}
    access:
      - channel: {chat: -1001234567890, days: 30, remind_days: [3, 1]}
      - message: {text: "Добро пожаловать, {first_name}!", files: [files/guide.pdf, files/bonus.zip]}
      - manager: {text: "Спасибо! Скоро вам напишем."}
```

### Элементы access

Список `access` описывает, что происходит после **успешной оплаты**. Элементы можно сочетать.

| Элемент | Ключи | Что делает |
|---|---|---|
| `channel` | `chat` (обязательно), `days`, `remind_days` | Выдаёт ссылку-заявку в закрытый канал или группу. С `days` доступ заканчивается через это время. `remind_days` (число или список, каждое меньше `days`) присылает напоминания о продлении за столько дней до конца. Без `days` доступ бессрочный |
| `message` | `text`, `file`, `files` | Сразу отправляет сообщение и/или файлы. Файлы загружаются один раз и переиспользуются |
| `manager` | `text` | Отправляет карточку в `manager_chat` и текст клиенту |

Повторная покупка того же канала продлевает доступ от текущей даты окончания.

Пути к картинкам и файлам считаются от папки с `funnel.yaml`. Можно также указать ссылку `https://` или `file_id:<id файла в Telegram>`.

## steps

```yaml
steps:
  welcome:
    text: "Здравствуйте, <b>{first_name}</b>!"
    image: files/hello.jpg
    buttons:
      - [{text: Подробнее, goto: about, style: primary}]
      - [{text: Купить, pay: club}, {text: Вопрос, manager: true}]
    nudges:
      - after: 3h
        text: "Всё ещё думаете?"
        buttons:
          - [{text: Показать предложение, goto: offer}]
```

| Ключ | Значение |
|---|---|
| `text` | Текст сообщения (обязательно) |
| `image` | Картинка, отправляемая с текстом |
| `buttons` | Ряды кнопок. Каждый вложенный список — один ряд (до 8 кнопок) |
| `next` | Шаг, на который перейти автоматически |
| `wait` | Вместе с `next`: подождать столько перед переходом |
| `ask` | Задать клиенту вопрос и дождаться ответа, затем перейти на `next` |
| `pay` | Показать под текстом кнопки способов оплаты этого продукта |
| `paid` | Шаг, который показать после покупки, сделанной на этом шаге |
| `nudges` | Напоминания, если клиент ничего не делает |
| `end` | `true` помечает финальный шаг (без предупреждения о тупике) |

Шаг только с `next` переходит дальше сразу, так можно выстроить цепочку сообщений.

### buttons

У каждой кнопки есть `text` и ровно одно действие:

| Действие | Значение | Результат |
|---|---|---|
| `goto` | id шага | Перейти на другой шаг |
| `pay` | id продукта | Открыть карточку продукта со способами оплаты |
| `url` | ссылка | Открыть ссылку |
| `copy` | текст (до 256 символов) | Скопировать текст в буфер (промокод, адрес) |
| `back` | `true` | На предыдущий шаг |
| `home` | `true` | На стартовый шаг |
| `manager` | `true` | Уведомить чат менеджеров и сказать клиенту, что ему напишут |

Дополнительные ключи: `style` (`primary` синяя, `success` зелёная, `danger` красная) и `icon` (id кастомного эмодзи, длинное число). Цвета и кастомные эмодзи требуют свежего приложения Telegram.

### ask

```yaml
  ask_email:
    text: "Какой у вас email?"
    ask: {key: email, type: email, error: "Это не похоже на email."}
    next: offer
```

`type`: `text`, `email`, `phone`, `number`, `choice` (с `choices: [S, M, L]`, показывается кнопками) или `regex` (с `regex: '\d{6}'`). Ответ сохраняется под `key`, виден в `/admin` → карточка клиента, выгружается `funnelbot export` и доступен как `{key}` в следующих текстах. Краткая запись `ask: name` спрашивает свободный текст и сохраняет его как `name`.

### nudges

Напоминания для клиентов, застрявших на шаге. `after` считается с момента, когда клиент пришёл на шаг. Каждое напоминание отправляется один раз и только если клиент всё ещё там. Оно пропускается, если клиент уже купил продукт из его кнопок, открыл оплату в последний час, заблокировал бота или нажал `/stop`. Если бот был выключен и подошли сразу несколько напоминаний, отправляется только последнее.

## Проверки, которые вы получаете бесплатно

`funnelbot validate` и «Перезагрузка» в панели проверяют, среди прочего: неизвестные ключи и шаги, кнопки без действия, тексты с неизвестными `{подстановками}`, отсутствующие файлы, цены без подходящего способа оплаты, чеки без контакта, функции менеджера без `manager_chat`, недостижимые шаги и тупики, а также цифровые продукты, продаваемые не за Stars (предупреждение со ссылкой на правила Telegram).
